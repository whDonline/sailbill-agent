# ADR 0001 · 确定性优先，模型只做语义

- 状态：已采纳
- 日期：2026-09-27

## 背景

账单抽取的核心风险不是"读不懂"，而是"读错还看不出来"。金额、币种、合计、匹配都是有唯一正确答案的
计算问题；让模型去做这些，等于把可验证的正确性换成不可验证的概率。

## 决策

能用代码算的，绝不给模型：

| 任务 | 归属 |
| --- | --- |
| 金额解析、合计校验、币种 ISO 校验 | 代码 |
| 费用名标准化、付款方式、主体归一 | 代码（词典 + 模糊） |
| 账单匹配、AR/AP、操作类型 | 代码（规则矩阵） |
| 版式理解、字段定位、模糊归属、理由生成 | 模型 |
| 双方冲突时的仲裁 | 代码（规则优先，见 ADR 0005 的反向情形） |

## 后果

- ✅ 无 Key 也能跑通全流程，评审零配置可验收；
- ✅ 模型故障时系统降级而不崩溃；
- ✅ 每个决策都能解释，符合财务审计要求；
- ⚠️ 词典需要持续维护（`normalize/charges.py` 已有 30+ 标准项、百余别名）；
- ⚠️ 罕见版式不如"纯 LLM"灵活 —— 由 `PENDING_REVIEW` 兜底，而不是硬猜。
