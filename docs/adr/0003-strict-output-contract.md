# ADR 0003 · 严格输出契约 + 扩展调试通道

- 状态：已采纳
- 日期：2026-09-27

## 背景

题面给出了精确的输出 schema（6 个顶层键、固定嵌套）。而系统内部自然会产生大量有用信息：
置信度、证据片段、匹配到的账单、变更字段、校验问题、耗时。

把这些直接加到输出里，会让下游财务系统解析失败，也会让"是否符合契约"变成扯皮。

## 决策

* **默认模式**：只输出题面规定的键，一个不多。用 `BillRecordOut`（`extra="forbid"`）固化；
* **`--extended`**：在 `_trace` 命名空间下附加全部调试信息；
* 任何新增字段都必须先改 ADR 与契约，不能"顺手加"。

## 后果

- ✅ 输出可直接被下游消费，schema 稳定；
- ✅ 调试信息不丢，`--extended` + `--trace` 足够定位问题；
- ⚠️ 例如"变更字段列表"这类业务上很有用的信息，默认输出里看不到（符合题面，但真实项目应推动契约升级）。
