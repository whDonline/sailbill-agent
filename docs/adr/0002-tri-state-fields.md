# ADR 0002 · 三态字段（present / absent / unknown）

- 状态：已采纳
- 日期：2026-09-27

## 背景

题面要求"无法提取的字段使用 `null`"。但如果内部也只用 `None`，就无法区分：

1. 单据里**没有**这个字段（例如小计=合计，本来就没有税额行）；
2. 单据里**有**这个字段，但 OCR 糊了/被截断/模型没读出来。

这两者在下游的处理**完全相反**：

* 情况 1 在更新时可以安全继承原账单值；
* 情况 2 绝不可以继承，也绝不可以写入 —— 必须人工复核。

## 决策

内部统一使用 `Tri[T] = (value, status, evidence)`，`status ∈ {present, absent, unknown}`：

* 只有 `present` 参与"是否需要变更"的比较；
* `absent` 允许继承；
* `unknown` 阻止写入，并降低置信度。

输出层仍然按题面把三类都压成 `null`（契约优先），三态信息进 `--extended` 的 `_trace`。

## 后果

- ✅ 彻底消除"OCR 失败把原账单金额覆盖成 null"这类事故；
- ✅ 置信度扣分有据可依（缺字段 vs 读不出，扣分不同）；
- ⚠️ 提取层要负责判断 `absent` 还是 `unknown`，实现复杂度上升；
- ⚠️ 下游若只拿到 `null` 会丢失该信息，需要 `--extended` 或契约升级（见 reflections §2）。
